# 需求与实现方案：按工作目录自动切换 API Key

## 需求

| 项 | 内容 |
| --- | --- |
| 提出日期 | 2026-09-14 |
| 需求来源 | 用户提出的功能新增（随 DSH 0.1.5-alpha.2 适配一并实施） |
| 配置入口 | 设置 ─► API Key 管理 ─► 各项目编辑面板「工作目录 dirs」 |
| 约束 | 一个目录只能绑定一个项目（目录与项目为多对一） |
| 场景 | 切换 workspace（会话激活）时判断当前目录，命中绑定则自动切换到对应项目的 API Key |

## 现状与差距

1. 插件已有「每会话记忆」（localStorage，键 `apikeyswitch.conv.<sessionId>`）：会话激活时静默恢复该会话上次选择的项目，属于「按会话」记忆，不是「按目录」绑定。
2. 元数据 `DSH_APIK_META` 只保存 `remark` / `provider` / `model` / `user` / `deleted`，没有目录字段。
3. 宿主可用的目录事实源有两个：live 会话的 `agent.session.header.cwd`（`dsh-session` 的 `SessionHeader.cwd`，绝对路径），以及 `workspaceRegistry.list()` 中各工作区实体的 `path` 与 `sessionIds`（`dsh-workspace`，启动时按会话 header 建立索引）。

## 实现方案

### 数据模型

`DSH_APIK_META` 每个项目新增可选字段 `dirs`：字符串数组，元素为绝对路径；同一目录不得出现在两个项目下。示例（占位路径）：

```json
{
  "example": { "user": true, "remark": "示例项目", "dirs": ["/REPLACE/WITH/WORKSPACE/PATH"] }
}
```

### Host 侧能力

| 函数 | 职责 |
| --- | --- |
| `normalizeDir(value)` | 目录归一化：去首尾空白、去结尾分隔符（仅用于比较） |
| `dirsOf(meta)` | 读取并归一化某项目的 `dirs`，去重去空 |
| `canonDir(dir)` | 用 `workspaceRegistry.resolveByPath()` 做真实路径归一；目录当前不存在时回落字符串归一 |
| `sameDir(a, b)` | 两个目录是否指向同一位置 |
| `findDirConflict(dirs, excludeId)` | 找出与给定目录冲突的其他项目 |
| `matchDirProfile(dir)` | 目录 → 绑定项目 |
| `resolveSessionDir(sessionId)` | 会话 → 当前工作目录：live 会话取 `agent.session.header.cwd`，否则遍历 `workspaceRegistry.list()` 的 `sessionIds` 取 `path` |
| `autoSwitchByDir(args)` | 目录自动切换主流程（RPC `auto`） |
| `resolveDirsArg(args, ownerId, ownerLabel)` | 保存/新增时的目录入参归一与唯一性校验 |

### RPC 契约

| action | 入参 | 返回 |
| --- | --- | --- |
| `auto` | `{ sessionId }` | `{ ok, matched, auto, switched, dir, dirProfile, ...status }`；未命中返回 `matched:false` 与 `dir`（可能为空）；命中但被运行会话守卫阻止时返回 `ok:false + guard:true + matched:true` |
| `save` | `{ id, remark, provider, model, dirs?, key?, renameTo? }` | `dirs` 存在时整体替换该项目的目录绑定 |
| `add` | `{ id, key, remark?, provider?, model?, dirs? }` | 同上 |
| `list` / `status` | 无 | 每个项目新增 `dirs` 字段 |

### 自动切换流程

```
会话激活（作曲栏下拉框挂载 / sessionId 变化）
  ─► Client rpc('auto', { sessionId })
       ─► Host resolveSessionDir(sessionId) 取当前目录
            ─► 无目录 ──────────────────────────────► matched:false
            ─► matchDirProfile(dir) 未命中 ──────────► matched:false
            ─► 命中且已是生效项目 ───────────────────► matched:true, switched:false
            ─► 命中但项目未配置 Key ─────────────────► matched:true, ok:false + error
            ─► 命中且需切换 ─► switchProfile(id, { guard:true, sessionId })
                 ─► 守卫放行（自身会话不计入其他会话）─► 写入生效槽 + 同步默认路由
                 ─► 守卫阻止（其他会话运行中）────────► matched:true, ok:false + guard:true
  ─► Client 处理：
       matched:true  ─► 目录绑定接管本次激活（成功弹「已按目录自动切换」Toast；
                        被守卫阻止弹阻止提示；两种情况都不再回落到会话记忆）
       matched:false ─► 回落既有「会话记忆」恢复逻辑
```

### 优先级与守卫

1. 目录绑定优先于会话记忆：会话激活时先看目录绑定，命中即接管；未命中才使用会话记忆。
2. 目录自动切换同样受运行会话守卫约束（防止跨会话 API Key 串用）：被阻止时保留绑定不写入，下次激活重试。
3. 手动切换（作曲栏、Run 卡片面板、模型工具）不受目录绑定限制，切换后在会话记忆留下记录；再次激活该会话时目录绑定仍会生效，这是「目录即事实」的既定语义。

### 不采用的替代方案

| 替代方案 | 不采用原因 |
| --- | --- |
| Client 用 `props.useWorkspaces()` 自行匹配目录 | 需要把工作区快照与会话归属在浏览器侧重建，且旧会话（无 live agent）与新建会话的归属判定容易与宿主不一致；Host 侧同时掌握 `header.cwd` 与 `workspaceRegistry` 两个事实源 |
| Host 监听 `session/created` 等事件自动切换 | 会话事件包含子代理会话，会引入与界面无感的全局切换；当前方案以「界面激活会话」为触发点，语义与用户操作一致且可解释 |
| 目录绑定允许一对多（同一目录绑定多个项目） | 与需求约束冲突；命中多项目时无法确定唯一目标 |
| 目录匹配只做字符串比较 | 用户输入可能带结尾分隔符或符号链接（macOS `/tmp` 与 `/private/tmp`），字符串比较会漏配；因此用 `workspaceRegistry.resolveByPath()` 归一 |

## 增量需求：目录选择按钮（2026-09-14 追加）

| 项 | 内容 |
| --- | --- |
| 需求来源 | 用户反馈：手动输入绝对路径不便，需要打开系统目录选择框 |
| 配置入口 | 「+ 添加目录」按钮（点击即打开选择框）；已选目录可「重选」或「移除」 |
| 实现方式 | RPC `pickDir` 调用宿主 `directoryPicker.capability().pick(signal)`；与「设置-工作区」的添加工作区同源，macOS 上为 Finder 选择框 |
| capability 契约 | 宿主 capability 的 kind 随 `status` 下发；仅 `native` 时渲染「选择」按钮，`browse`/`unavailable` 时隐藏入口（远程/SSH/无显示会话的部署改为手动填写路径） |
| 取消语义 | 用户在系统对话框点取消时返回 `{ ok:true, cancelled:true }`，界面保持原值不报错 |
| 并发生命周期 | 选择期间的 HTTP 请求保持连接；浏览器页面关闭（响应对象 close）时 abort 选择框，避免留下无人处理的原生进程 |
| 记录展示 | 选中后生成一条记录：主行显示目录名（路径最后一段），下方小字显示完整绝对路径，整行 hover 可见完整路径 |
| 重复处理 | 同一项目内重复选择同一目录时不新增记录并提示「该目录已在列表中」；跨项目重复在保存时由 Host 拒绝 |

## 配置与使用

1. 设置 ─► API Key 管理 ─► 编辑项目 ─► 工作目录 dirs ─► 添加目录（绝对路径）─► 保存。
2. 目录冲突校验：若目录已被其他项目绑定，保存被拒绝并提示占用的项目与目录，需先从该项目移除。
3. 生效：切换到该目录的 workspace（打开或新建其中的会话）即自动切换；作曲栏下拉框顶部显示「目录：<path> → <项目>」。

## 验证计划

| 序号 | 验证点 | 方式 |
| --- | --- | --- |
| 1 | 目录绑定保存与回读 | `save` 带 `dirs` 后 `list` 返回相同目录 |
| 2 | 目录唯一性 | 同一目录绑定第二个项目被拒绝并返回占用信息 |
| 3 | 目录归一化 | 带结尾分隔符的同一目录同样判定为冲突 |
| 4 | 命中自动切换 | 打开绑定目录内的会话，生效项目切换为绑定项目，作曲栏标签同步 |
| 5 | 跨 workspace 切换 | 从项目 A 的 workspace 切到项目 B 的 workspace，Key 随目录切换 |
| 6 | 未命中不误切 | 未绑定目录的会话激活不改写生效槽 |
| 7 | 目录提示 | 作曲栏菜单显示当前目录与绑定项目 |
| 8 | 目录选择流程（增量） | native capability 下点击「+ 添加目录」发起一次 `pickDir` 并新增一条「目录名 + 完整路径」记录；「重选」替换该行路径 |
| 9 | 能力分支（增量） | browse capability 下不渲染「选择」按钮，`pickDir` 返回明确错误文案 |
